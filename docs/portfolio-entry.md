# Crush portfolio and resume copy

## Portfolio description

**Crush — AI Marketing Command Center**

I built Crush to explore how the repetitive parts of marketing analysis could be automated without handing the truth over to a language model. It is a Next.js application that combines Google Ads reporting, optional GA4 context, deterministic account audits, completed-period daily analysis, weekly reporting, grounded AI insights, and a conversational “Ask Your Marketing Data” workspace.

The project draws directly on my hands-on digital marketing experience: knowing which metrics need context, where attribution comparisons become misleading, and why a recommendation should show its evidence. Code calculates the facts and prepares supported findings; OpenAI is limited to structured selection and prioritization in specific workflows, and returned evidence is validated before display. A clearly labeled fictional account keeps the portfolio demo useful without credentials, while server-only adapters support read-only live integrations.

Crush is a personal learning project and a practical demonstration of how I use AI-assisted software development to turn marketing domain knowledge into a working product. It is not presented as a client deployment or as proof of revenue, conversion, or cost-saving outcomes.

## LinkedIn / project description

I built **Crush**, an AI marketing command center, as a personal learning and portfolio project. It combines the work I know from hands-on digital marketing—paid-media analysis, measurement caveats, account audits, and recurring reporting—with AI-assisted modern application development.

Crush can load read-only Google Ads data and optional GA4 context, or open immediately with a clearly labeled fictional account. The part I care about most is the trust model: code owns metrics, thresholds, and evidence. OpenAI is used only in bounded structured workflows, and unsupported output is rejected. This project is not a claim of client results; it is a working demonstration of how I turn marketing-domain problems into testable product and technical decisions.
